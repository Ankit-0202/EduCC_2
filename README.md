# EduCC Compiler Overview

EduCC is a teaching-oriented C compiler that emits LLVM IR and relies on the
host toolchain to produce native executables.  Recent improvements focus on
behaving like other hobby compilers that reuse system components instead of
rolling bespoke linkers or C runtimes.

## Prerequisites

- LLVM (tested with Homebrew LLVM 21.1.5) for headers/libraries plus
  `llvm-config`, `clang`, and `llc`.
- A host C toolchain for comparison tests (defaults to `gcc`).
- POSIX shell utilities (the Makefile assumes macOS or Linux).

### Environment Variables

The compiler automatically considers the following environment variables:

- `CPATH`, `C_INCLUDE_PATH`, `CPLUS_INCLUDE_PATH` augment header search paths.
- `LIBRARY_PATH`, `LD_LIBRARY_PATH` (or `DYLD_LIBRARY_PATH` on macOS) provide
  additional library search directories during linking.

## Building

```sh
make            # builds build/educc and supporting static libraries
```

Clean artefacts with `make clean`.

## Usage

```
build/educc <source.c> [output.ll] [options]
```

Key options:

- `--exe <path>`: override the executable output path (defaults to the source
  stem or `a.out`).
- `--no-link`: generate LLVM IR only.
- `--linker <path>`: use a different linker driver (defaults to `clang`).
- `--lib <name>` / `--lib-path <dir>`: add libraries or search directories.
- `--linker-arg <arg>`: forward extra arguments to the linker.
- `--no-default-libs`: suppress default library injection
  (translates to `-nodefaultlibs` for clang).
- `--link-verbose`: print the constructed linker command.
- `--link-from-ir <path>`: bypass the front-end and link an **existing** LLVM IR
  file using EduCC’s linker pipeline.  This is useful when IR is produced by an
  external tool such as `clang -S -emit-llvm`.

Example end-to-end compilation:

```sh
build/educc hello.c                  # emits output.ll and a.out
build/educc --link-from-ir foo.ll --exe foo   # link pre-generated IR
```

During linking EduCC shells out to `clang`, automatically deduplicates library
flags, appends `-L` for discovered library paths, reuses system defaults
(`libc`, `libm`), and suppresses the noisy `-Woverride-module` diagnostic when
consuming textual IR.

When the in-tree preprocessor cannot handle complex system headers, EduCC
falls back to `clang -E` transparently, ensuring system headers remain
available without bespoke vendor copies.

## Testing

Integration tests live under `tests/` with a dedicated linker suite in
`tests/integration/linker`.  The entire suite is driven by `pytest`, which
compares the exit code **and** the standard output of each test program as
produced by EduCC versus the system toolchain (`gcc` by default).

```
pip install pytest             # once
make test                      # run the full suite
make test-linker               # only the linker integration tests
pytest -k arrays               # ad-hoc selections
```

Each PyTest case is individually named after the relative path of the input
`.c` file, making it straightforward to apply markers or overrides for
per-test behaviour in the future.

## Notes

- The current front-end is intentionally minimal and does not yet parse full
  system headers.  The `--link-from-ir` option ensures we can still validate
  linker behaviour using IR generated by clang.
- Default library flags (`-lc`, `-lm`) are injected unless disabled with
  `--no-default-libs`.
- Verbose mode shows the exact command EduCC executes, making it easier to
  iterate on linker arguments.
